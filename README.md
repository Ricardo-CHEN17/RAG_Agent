# Local Agentic RAG CLI

An offline, command-line, agentic RAG assistant powered by a local Ollama model, ChromaDB, and optional MySQL support. The agent can plan multi-step tasks, call tools, inspect local files, and search a local knowledge base without sending data to external APIs.

## Project Features

- Fully local execution for privacy-focused workflows.
- Agentic loop with iterative tool calling and observation.
- File system tools for listing directories and reading text files.
- Retrieval-augmented generation over a local ChromaDB vector store.
- Optional read-only MySQL query tool for structured data lookup.
- Simple CLI REPL with exit commands and log output.
- Unit tests covering the controller, tools, and RAG pipeline.

## Repository Layout

- `main.py` - CLI entry point and dependency wiring.
- `agent/` - message models, Ollama client, and agent controller.
- `tools/` - file, RAG, MySQL, and tool execution helpers.
- `knowledge/` - embedding, vector store, and document indexing.
- `db/` - MySQL client wrapper.
- `tests/` - pytest test suite.
- `logs/` - runtime logs generated by the application.

## Requirements

- Python 3.10+ is recommended.
- Ollama installed locally and running.
- A local model available in Ollama.
- Optional: MySQL if you want to use the SQL tool.

## Installation

1. Create and activate a virtual environment.
2. Install dependencies:

```bash
pip install -r requirements.txt
```

3. Make sure Ollama is running locally.

## Configuration

Create a `.env` file in the project root and configure the values you need:

```env
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL_NAME=gemma4
CHROMA_PERSIST_DIR=./chroma_data

MYSQL_HOST=localhost
MYSQL_USER=root
MYSQL_PASSWORD=your_password
MYSQL_DATABASE=agentic_rag
```

### Configuration Notes

- `OLLAMA_BASE_URL` points to the local Ollama server.
- `OLLAMA_MODEL_NAME` controls which local model is used by the agent.
- `CHROMA_PERSIST_DIR` sets where the embedded vector store is stored.
- The MySQL settings are optional. If they are missing or invalid, the agent still works without the SQL tool.

## Usage

### 1. Start the CLI agent

```bash
python main.py
```

After startup, the program enters a REPL loop. Type your question and the agent will decide whether it needs to call tools before answering.

Available exit commands:

- `.exit`
- `.quit`

### 2. Build the local knowledge index

The indexer currently supports `.txt` and `.md` files. There is no dedicated CLI command yet, so you can run it from a short Python script or an interactive shell:

```python
from knowledge.embedder import Embedder
from knowledge.vector_store import VectorStore
from knowledge.indexer import Indexer

embedder = Embedder()
vector_store = VectorStore(persist_dir="./chroma_data", embedder=embedder)
indexer = Indexer(vector_store=vector_store)

indexer.index_directory("./docs")
```

Once the documents are indexed, the agent can search them through the `search_knowledge` tool.

### 3. Ask questions

Examples:

- Summarize the files in this folder.
- Search the knowledge base for notes about project requirements.
- Read the content of `Plan.md` and explain the current status.
- If MySQL is configured, query a table with read-only SQL.

## How It Works

1. `main.py` loads environment variables and initializes all components.
2. `AgentController` sends the user message to Ollama along with tool definitions.
3. If the model requests a tool call, `ToolExecutor` routes the call to the correct implementation.
4. Tool results are fed back into the agent loop until the model returns a final answer or the iteration limit is reached.

## Supported Tools

- `list_files` - list directory contents.
- `read_file` - read a local text file.
- `search_knowledge` - search the local ChromaDB knowledge base.
- `mysql_query` - execute a read-only `SELECT` query when MySQL is configured.

## Current Limitations

- No web search or external API integration.
- No GUI; this is CLI-only in v1.
- The indexer currently supports `.txt` and `.md` files only, so PDF support is still pending.
- There is no built-in `python -m knowledge.indexer --path ...` command yet.
- The SQL tool is read-only and optional.

## Testing

Run the test suite with:

```bash
pytest
```

The tests cover the agent controller loop, file tools, retrieval tool behavior, and the vector store/indexing flow.
